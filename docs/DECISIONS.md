# Design decisions

Each real choice, written when it was made. Newest at the bottom.

| # | Date | M | Decision | Options considered | Why | Revisit if |
|---|---|---|---|---|---|---|
| 1 | 2026-11-20 | M0 | **Flyway owns the schema**; Hibernate only checks it (`ddl-auto=validate`) | `ddl-auto=update`; Liquibase | Every schema change is a versioned, reviewed SQL file, so every machine and CI gets the same schema. `update` changes tables silently, can't rename or drop safely and leaves no history, which is not acceptable for money data. Liquibase does the same job; Flyway is plain SQL and simpler | The team already standardises on Liquibase |
| 2 | 2026-11-20 | M0 | **All time in UTC** (JVM runs with `-Duser.timezone=UTC`; times stored as `Instant` / `timestamptz` from M1) | Local time (`Asia/Kolkata`); leave the JVM default | One unambiguous timeline: "when did this transfer happen" gives the same answer on every server, with no daylight-saving gaps or duplicates. Convert to local time only for display. Also fixed BUGLOG #1 | Never for storage; only display formatting changes |
| 3 | 2026-11-20 | M0 | **PostgreSQL in Docker Compose** for local dev | Local Postgres install; H2 in-memory DB | Same database as production with one command (`docker compose up -d`) and nothing installed on the PC. H2 behaves differently from Postgres (locking, SQL dialect), which matters for the M4 concurrency work | The project moves to a managed cloud database (keep Postgres) |
| 4 | 2026-11-20 | M0 | **Java 21 (LTS)** | Java 25 (newest LTS); Java 17 | Builds with the installed JDK 22 and is the most widely used version in industry. Java 17 lacks virtual threads and record patterns; Java 25 needs a new JDK for no feature this project uses yet | A Java 25 feature becomes useful, or a deployment target requires it |
| 5 | 2026-11-20 | M0 | **Spring Boot 4 + Maven, project generated by Spring Initializr** | Hand-written `pom.xml`; Gradle | The starter parent keeps all library versions compatible, and the `mvnw` wrapper means no Maven install is needed. My older E-Commerce project used hand-picked versions, which caused version drift and the Tomcat 9 / `jakarta` mismatch | The build needs features Maven handles poorly (then consider Gradle) |
